Change an alert rule's lifecycle or responder metadata without recreating it. Use is_disabled=false to promote/enable a validated rule, is_disabled=true to pause it, mute_until to mute or unmute it, and properties to replace its description, runbook, annotations, or query_mode. At least one change is required. This endpoint returns no replacement ID because PATCH preserves the existing rule ID. An entity-level snooze can prevent rule-level mute changes.
 Use recurring_mute_schedule to replace the rule's weekly mute schedule: {enabled (bool, default false), timezone (IANA name such as Asia/Kolkata, required), windows (required, 1-20 entries of {weekdays: 1-7 of sun, mon, tue, wed, thu, fri, sat; start_time and end_time as 24-hour HH:MM in that timezone, which must differ; an end at or before the start ends the next day})}. The whole schedule is replaced, so send every window to keep. To remove the schedule entirely, set clear_recurring_mute_schedule=true (default false; cannot be combined with recurring_mute_schedule); this differs from sending enabled=false, which pauses the schedule but keeps its windows stored. Notifications are suppressed while a window is active. Access: viewer-role users may only change mute_until on its own; pausing, properties, recurring_mute_schedule, clear_recurring_mute_schedule and all other changes need editor access, and a 403 is returned as a tool error saying so.
