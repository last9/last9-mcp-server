Create a custom dashboard. Pass the API envelope `{dashboard, metadata}`. `dashboard` needs `name` and `panels`. Each panel needs `name`, `layout: {x, y, w, h}`, and `visualization: {type}`. Query panels also need `queries`; section and markdown panels do not. Non-section panels may omit `version` and default to `version: 1`; logs panels must explicitly set `version: 1`, and section panels stay versionless. A logs visualization also needs `logs_config: {columns: [...]}` with one or more of `timestamp`, `reason`, `severity`, `kind`, `service`, or `body`, and exactly one logs query of type `log_ql` or `log_raw`. Do not use `gridPos` or a panel-level `type`.


Each query needs `name`, `type`, `query_type`, `telemetry`, `expr`, and `legend: {type, value}`. Legend `type` is `auto` or `custom`; use `auto` unless an explicit label is needed. Use `promql` for metrics, `log_ql` or `log_json` for log charts, `log_ql` or `log_raw` for raw log panels, and `trace_ql` or `trace_json` for traces; `logs` is a telemetry value, not a query type. Every `log_json` expression must be a JSON pipeline with an aggregate stage. For `log_json` line, timeseries, or bar panels, include exactly one aggregate with a time window; grouping by service or environment does not replace the window. Example: `[{"type":"window_aggregate","function":{"$count":[]},"as":"count","window":["5","minutes"],"groupby":{"ServiceName":"service"}}]`. Use a discovered valid expression; do not invent metric names. For panels, use discovery only to find their expressions; do not query live logs or traces as previews, and stop after finding one valid expression per panel. Example shape: `{"dashboard":{"name":"Example","panels":[{"name":"Request rate","version":1,"layout":{"x":0,"y":0,"w":12,"h":8},"visualization":{"type":"timeseries"},"queries":[{"name":"A","type":"range","query_type":"promql","telemetry":"metrics","expr":"up","legend":{"type":"auto","value":""}}]}]},"metadata":{"_category":"custom","_type":"metrics"}}`.

Use this tool only for a net-new dashboard (no id yet). Create once. After this tool returns, keep dashboard.id and call update_dashboard for any panel, layout, or query change — including later in the same turn. If an id was returned this turn or is already known, do not call create_dashboard again.

For `log_json` line, timeseries, or bar panels, use a `window_aggregate` stage with a `window`; a plain `aggregate` stage does not satisfy the API's timeslice requirement. When the user supplies a service, use it without calling `get_service_profile`, `get_service_environments`, or `did_you_mean`; discover only the metric expressions required by the panels.

On a timeout or connection error the create may or may not have been applied; check by name with list_dashboards before retrying.
