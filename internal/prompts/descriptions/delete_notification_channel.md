Permanently delete a notification channel. Use it only when the user wants the channel itself gone; to stop one alert group notifying a channel, use detach_notification_channel instead. Parameters: channel_id (required, an integer such as 42) is the id column of get_notification_channels with scope=channels; it is NOT an attachment id, and the tool refuses attachment ids. To clean up, remove test leftovers or act on several channels at once, act only on channels whose created_via is last9-mcp (shown by get_notification_channels scope=channels); remove any other channel only when the user names that specific channel or explicitly says to include ones created elsewhere. The channel must have no attachments: if any alert group still routes to it the call is refused, so detach those attachments first with detach_notification_channel (find them with get_notification_channels scope=attached). Deletion is permanent and cannot be undone; confirm with the user before calling. Requires a delete-scope token: a write-scope token cannot delete. The result is checked by re-listing channels, so a delete the API did not apply is reported as an error. Repeating is refused because the channel is gone. Returns the deleted channel id, name and type, plus a link to notification channels in the result's _meta.reference_url. Never repeat secrets (webhook URLs, routing keys, headers) back to the user; this tool does not return them.
