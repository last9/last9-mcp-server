Create a custom dashboard. Pass the API envelope `{dashboard, metadata}`. `dashboard` needs `name` and `panels`. When the user provides only a name, use `panels: []`; do not invent metrics or queries. Each panel needs `name`, `layout: {x, y, w, h}`, and `visualization: {type}`. Query panels also need `queries`; section and markdown panels do not. CSV-backed table/chart panels use a `csv` object and dashboard-level `csv_datasource` instead of remote `queries`. Non-section panels may omit `version` and default to `version: 1`; section panels stay versionless. Do not use `gridPos` or a panel-level `type`. Use `promql` for metrics, `log_ql` or `log_json` for logs, and `trace_ql` or `trace_json` for traces; `logs` is a telemetry value, not a query type. For a raw-log visualization (`visualization.type: "logs"`), use `query_type: "log_raw"` with `telemetry: "logs"` and a non-aggregate JSON pipeline in `expr`.

Each query needs `name`, `type`, `query_type`, `telemetry`, `expr`, and `legend: {type, value}`. Use a discovered valid expression; do not invent metric names. Example shape: `{"dashboard":{"name":"Example","panels":[{"name":"Request rate","version":1,"layout":{"x":0,"y":0,"w":12,"h":8},"visualization":{"type":"timeseries"},"queries":[{"name":"A","type":"range","query_type":"promql","telemetry":"metrics","expr":"up","legend":{"type":"auto","value":""}}]}]},"metadata":{"_category":"custom","_type":"metrics"}}`.

Use this tool only for a net-new dashboard (no id yet). Create once. After this tool returns, keep dashboard.id and call update_dashboard for any panel, layout, or query change — including later in the same turn. If an id was returned this turn or is already known, do not call create_dashboard again.
