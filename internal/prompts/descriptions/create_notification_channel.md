Create a notification channel (Slack, PagerDuty, Opsgenie, email or generic webhook) that alerts can notify. Creating a channel does not route any alerts to it: afterwards call attach_notification_channel with the returned id and an alert group id from get_alert_groups. Create once and keep the returned id; there is no update tool, so to change a channel use the Last9 UI, and do not create a second channel to "retry" (same name and type, or the same destination, is rejected as already existing; find the existing id with get_notification_channels scope=channels). Parameters: name (required; unique per type, no colon), type (required: slack, pagerduty, opsgenie, email, generic_webhook), destination (required; slack: an https://hooks.slack.com/ Incoming Webhook URL, or a Slack channel ID when slack_app_mode is true; pagerduty: routing key; opsgenie: API key; email: comma-separated work addresses on any domain, not only the org's; the API rejects personal-provider addresses such as Gmail, and an org on a personal login accepts only its admin's address; generic_webhook: HTTPS URL). Optional: slack_app_mode (slack only, default false), mention_handles (comma-separated, e.g. user|U123ABC|name, usergroup|S123ABC|name, special|here or special|channel; default none), webhook_headers (generic_webhook only, string map of HTTP headers, default none), webhook_ca_certificate (generic_webhook only, one PEM CA certificate up to 64 KiB for a private CA, default none), send_resolved (default true; also notify on resolve). Requires a write-scope token whose owner is an editor or admin. Returns only id, name, type and send_resolved plus a link to notification channels. Never repeat secrets (webhook URLs, routing or API keys, headers, certificates) back to the user; the tool never returns them and error messages do not include upstream response bodies.
