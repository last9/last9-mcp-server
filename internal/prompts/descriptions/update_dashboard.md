Update a custom dashboard by ID. Same `{dashboard, metadata}` envelope and same panel/query shape as create_dashboard (full replacement): panels use `layout` and `visualization`; query panels also use `queries`; section and markdown panels do not. CSV-backed table/chart panels use a `csv` object and dashboard-level `csv_datasource` instead of remote `queries`. Non-section panels may omit `version` and default to `version: 1`; section panels stay versionless. Each query uses `name`, `type`, `query_type`, `telemetry`, `expr`, and `legend: {type, value}`. Use `promql` for metrics, `log_ql` or `log_json` for logs, and `trace_ql` or `trace_json` for traces; `logs` is a telemetry value, not a query type. For a raw-log visualization (`visualization.type: "logs"`), use `query_type: "log_raw"` with `telemetry: "logs"` and a non-aggregate JSON pipeline in `expr`. Readonly system dashboards return an error.

Prefer this tool for panel, layout, or query changes after create. Pass the existing dashboard id; do not call create_dashboard to refine a dashboard that already has an id.
