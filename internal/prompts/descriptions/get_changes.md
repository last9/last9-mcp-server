Build a scoped view of what changed during an absolute time range. Use this for incident chronology, nearby deployments or resource lifecycle changes, and configuration-change investigation. Results are assembled at request time; this is not a persisted ledger, and temporal proximity does not establish causality.

start_time and end_time are required RFC3339 timestamps. Provide at least one exact scope field: service, environment, cluster, namespace, resource_kind, resource_name, or resource_uid. sources optionally selects change_events and/or kubernetes_events; both are queried by default. categories filters the normalized result. order is asc by default or desc. limit uses the API default when omitted and accepts 1-500. cursor is opaque: pass it back unchanged from a previous response.

Treat evidence=explicit as a recorded Change Event and evidence=inferred as an exact built-in Kubernetes classification. Check timestamp_basis before interpreting occurrence time. Respect each source's query_status and configuration_status independently; partial results remain useful. Observations and unknown Kubernetes events are suppressed from changes but counted in source metadata. Do not infer system health, incident cause, or remediation from this response alone.
