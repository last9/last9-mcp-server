Dry-run an alert rule expression against an alert group's KPIs without saving anything. Use it before create_alert or update_alert. Parameters: entity_id (required, alert group/entity UUID), expression (required, arithmetic over indicators named by their KPI's exact name; at most 3 indicators), indicators_used (required, non-empty; map of each indicator name used in the expression to its KPI UUID owned by entity_id; get the KPI UUIDs from get_alert_config or get_entity_alert_rules). Use each KPI's exact name as its indicator name: this dry-run accepts any name, but create_alert and update_alert reject expression_args keys that are not the bound KPI's name. Write names with spaces, dots or dashes as-is (for example Test Alert / errors), exactly as create_alert saves them. Only the arithmetic expression over indicators is checked: pass the inner metric expression, not an adaptive_std_cmp(...) wrapper (wrappers fail to parse), and condition and alert_condition are never checked. The check that the indicators yield at least one timeseries together over the last hour runs only when the expression uses more than one indicator. Returns {"valid":true} or {"valid":false,"reason":"..."} describing why it is invalid ("invalid indicator details for X" means that UUID is not a KPI of this alert group); an invalid expression is a normal result, not a tool error.
