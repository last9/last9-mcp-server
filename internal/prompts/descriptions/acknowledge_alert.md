Take ownership of a firing alert during incident response, or release that ownership. Acknowledging records the owner of the API token as the alert's owner, which shows as the claim on the alert in get_alerts and in the Last9 Alerting UI; it does not resolve the alert, change its rule, or mute it. Parameters: alert_group_id, rule_id and rule_type (all required; copy them from the alert in get_alerts), action (optional; "ack" takes ownership and is the default, "unack" releases it), and mute_until (optional, ack only; Unix epoch seconds, 0 or omitted means none). ack first checks that get_alerts lists that exact alert (same three values) within the last hour, and refuses without recording anything otherwise. mute_until does NOT mute anything: it only records a mute you already applied with mute_alert_group or patch_alert, so apply the mute first and pass the same deadline here. Acknowledging an alert you already own is a safe no-op that returns the existing claim, so retrying is fine; acknowledging one owned by another user fails and names get_alerts as the place to see the owner. Only the owner or an org admin can unack. Requires a write-scope token whose owner has the editor or admin role (viewers only if the org enables viewer acknowledgement). An alert must be acknowledged before it can be handed to someone else with reassign_alert. Returns the claim: owner name and email, claimed_at (Unix seconds) and muted_until for ack, or {"released":true} for unack, plus a link to Alerting.
